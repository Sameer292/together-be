# Deployment checklist

Build the Dockerfile and run separate API and worker processes with runtime secrets. Set `NODE_ENV=production`, `PROVIDER_MODE=supabase`, `BILLING_MODE=revenuecat`, explicit policy limits, Supabase URL/keys, TLS PostgreSQL runtime URL, RevenueCat credentials, and private Storage bucket. Run reviewed migrations with the separate migration role before starting the runtime image. The API binds `PORT`; `/v1/live` checks process health and `/v1/ready` checks PostgreSQL. The worker needs a graceful shutdown period at least as long as its longest external request.

Put the API behind a TLS reverse proxy. Preserve real peer IP at the transport layer or add a trusted edge limiter; the application ignores client supplied forwarding headers. Keep SQL/Auth/Storage/RevenueCat credentials on backend/worker infrastructure only. Disable Supabase Data API, enable email-code templates, create the private bucket, configure store products and signed RevenueCat webhooks, and run sandbox integration checks. Those provider/dashboard actions cannot be done from this repository. Do not deploy until a real PostgreSQL migration and integration run and live provider configuration have been validated.
